# 家庭日用品库存 — 产品设计

本文给实现用。只描述产品、数据、计算和界面，不包含实现代码。应用是 Android 手机上的本地库存：记录日用品、记下使用、估计何时该补。无账号，无后端，数据不出这部手机。

界面只让用户做这些事：新购、点数、消耗、废弃，以及为一段时间选择住所和居住者。首页每一行只有三个数：在手数量、一个消耗速度、一个用完时间。方案、权重、每种居住组合各自的速度，都只存在于计算里，不要出现在界面上。

## 1. 产品一句话

用户在一部手机上管理一个或多个住所的日用品。库存按住所分开。消耗按「这个住所里、这几天到底是哪几个人」分开，不按人数档合并。用完日按未来每一天的居住者集合往前减。快过期单独提醒。

## 2. 已经定下的规则

1. **点数就是盘点。** 它把在手数量改成用户数到的数量。它不是购买，也不是用户手填的一笔消耗。
2. **盘点会自动算出消耗。** 账面已经包含上次结存之后的新购、显式消耗和废弃。推算消耗 = max(0, 账面 − 实盘)。这笔是真实消耗，进入速度。实盘高于账面的部分是盈余调整，不是负消耗，不进入速度，也不进价格图。
3. **显式消耗仍然保留，同一批数量不算两次。** 显式消耗发生时已经减少账面，盘点的推算消耗只含还没记过的缺口。有显式消耗的那一天，整天归那天的居住者集合，不再参加同一天的按天分摊。
4. **一个情况 = 一个住所 + 一组具名居住者。** 集合要完全相同才是同一个情况。{A} 和 {B} 不同，即使都是 1 个人。{A,B} 和 {A,C} 不同。人数只是这个集合的大小，不能当输入，也不能当情况的标识。
5. **不从成员推速度，也不除以人数。** {A,B} 的速度不是 {A} 加 {B}，不是它们的平均，也不是某个速度除以 2。没有自己的消耗记录时，速度未知，不能抄另一组人。
6. **周、月、年只决定哪些近期记录进入计算。** 周 = 最近 7 个日历日，月 = 最近 30 个，年 = 最近 365 个。全应用只有一个选择，默认周。回看里面仍按居住者集合拆开，不会把整段回看当成一种住法。
7. **后台有四种算法。** 用户看不见它们的名字、权重和分摊分数。每次记账或修改居住之后重算。权重不是一项用户设置，也不保存成用户能改的偏好。
8. **用完日按天往前走。** 已经写下的未来日期用写下的居住者。没写的日期，按该住所最近 7 天的星期几重复。人在这个用品的住所时，减去那一天那个集合的速度。这一天这个住所没有人，库存不减。另一个住所的日子也不减这个住所的库存。
9. **首页的那一个速度，等于从现在走到用完所减掉的数量，除以走过的天数。** 因此它和用完时间一致。它不是把某一组人的速度单独摆出来。
10. **快用完默认 5 天，快过期默认 3 天。** 两个提醒分开。每个用品可以各自改这两个天数。首页用该用品的快用完天数，临期页用该用品的快过期天数。
11. **同一住所里，品牌 + 规格相同的购买归入同一个用品。** 另一个住所里同名同规格是另一个用品。住所之间不调拨。
12. **实付单价 = (购买价格 − 优惠金额) / 数量。** 购买价格是优惠前总价。价格图画实付单价。选中购买点时显示购买数量、优惠金额、购买价格、实付单价、渠道，并能打开那一笔的截图。
13. **在手 = 各批次剩余之和。** 每次新购是一个批次。扣减先到期先出（没有到期日的最后）。消耗和废弃都减库存。废弃不进速度。盘点推算出来的消耗进速度。
14. **同一住所在同一个日历日只能有一组居住者。** 日期重叠是错误，用户自己改。同一个人不能在同一天出现在两个住所，这也是错误。不同的人可以在同一天分处两个住所。
15. **删除住所必须确认。** 文案写明库存、批次、照片和历史会被永久删除，并且不会转到别的住所。
16. **删除已经出现在居住记录里的人，不改写历史速度。** 过去的集合仍按删除前的名字显示，仍是原来的集合。

补充约定：

- 界面语言是中文。金额用人民币分存储，界面显示元，保留两位小数。数量最多三位小数，内部不用二进制浮点做加减。
- 每个用品有自己的单位。同一用品的购买、消耗、废弃、盘点都用这个单位。
- 日期都按本地日历日，开始日和结束日都算在内。星期一到星期日是 7 天。
- 没写结束日在将来的日子，不把「今天的人」一直铺下去。
- 提醒只在应用内的首页和临期页，不发系统通知。
- 不做云备份、账号、导出。不预置示例商品。往前走时不臆造未来的购买。
- 新购的数量保存后不能改。价格、优惠、渠道、到期日和截图可以改。消耗、废弃、盘点、新购可以删除；删除后重放，库存不能变成负数。
- 往前走最多 366 天。到那时仍没用完，显示「一年内不会用完」。

## 3. 导航

底部三个入口：首页、临期、住所。

```
首页
  ├─ 快用完列表 → 用品详情
  ├─ 新购 / 点数 / 消耗 / 废弃
  └─ 全部库存 → 用品详情
        ├─ 价格图与截图
        ├─ 批次
        └─ 两个提醒天数
临期 → 用品详情
住所
  ├─ 新增 / 删除住所
  ├─ 居住者：添加、改名、删除
  └─ 为一段时间选择住所和居住者
```

顶栏切换正在查看的住所。这只改列表，不改居住记录，也不搬库存。看「家」时不出现「父母家」的用品。

## 4. 页面

### 4.1 首页

快用完列表的每一行只有：

- 品牌、规格
- 在手数量和单位
- 一个消耗速度
- 一个用完时间
- 该用品自己的快用完天数，例如「5 天内提醒」

不要在这一行写出 {A}、{A,B}、5/7、2/7、方案或权重。

列入条件：在手为 0，或者用完日的日期 ≤ 今天 + 该用品的快用完天数。用完日未知且在手大于 0 时不列入。在手为 0 时列入，用完时间写「已经用完」。

排序：在手为 0 在前，其余按用完时间从早到晚。

四个按钮：新购、点数、消耗、废弃。用品只列出正在查看的住所。

空状态：没有住所时去添加居住者并写下住在哪；没有用品时去新购；没有达到快用完天数时说明目前没有要补的。

统计范围放在首页的设置里，标签是「统计范围」，选项是周、月、年，默认周。说明只用这段时间里的记账来估计用量。不要解释权重。

### 4.2 库存列表

每行：品牌、规格、在手、用完时间（或「无法估算」，或「一年内不会用完」）。可按品牌、规格在本地搜索。

### 4.3 用品详情

显示和首页相同的那一个速度、那一个用完时间，以及品牌、规格、单位、住所、在手。可以改快用完天数和快过期天数，新建时是 5 和 3，允许 0 到 365 的整数。0 表示只在已经用完，或到期日就是今天及更早时提醒。

用完日算不出来时，写「无法估算」。可以用居住者的名字说明接下来的组合还没有用量记录，仍然不要给出各组的速度、分数或权重。

下面是价格图、批次和四个记账入口。

### 4.4 新购

住所、品牌、规格、单位。同一住所里品牌 + 规格相同则并入原用品。数量大于 0。购买价格是优惠前总价，大于等于 0。优惠大于等于 0 且不超过购买价格。渠道必填。购买时间默认现在。到期日可空。截图可多张。表单实时显示实付单价。新购不是消耗。

### 4.5 点数（盘点）

显示账面。用户填写大于等于 0 的实盘数量。提交前预览差额：

- 实盘更少：记入推算消耗，并说明它会计入用量
- 实盘更多：记入盈余，说明这不是购买、不是负消耗、不计入用量
- 相等：库存不变

同时写明已经记过的消耗和废弃不会再算一次。不要在预览里展示 5/7 这种分摊。

### 4.6 消耗

用品、数量（大于 0）、日期（默认今天）。先到期先出。超过在手就拒绝。这一天这个住所有居住者时，整笔归那天的集合。这一天没有居住记录时仍可扣库存，并提示这笔不会进入用量估计。

### 4.7 废弃

与消耗相同，另加可空原因。减库存，不进任何速度。

### 4.8 临期

一行一个批次。剩余大于 0、有到期日，且到期日 ≤ 今天 + 该用品的快过期天数。已过期也算。没有到期日的不出现。剩余为 0 的不出现。

显示品牌规格、剩余、到期日、已过期几天或还要几天、渠道、该用品的快过期天数。已过期的排在前面。页上说明这里只看到期，默认 3 天，每个用品可以改。

### 4.9 住所、居住者和居住日期

居住者是人，不是数字。全应用一份名单，不隶属于某一个住所。可以添加、改名、删除。

改名只改显示，不重算速度，集合仍是同一些人。

删除一个已经用在居住日期里的人：过去的每一天仍显示删除前的名字，速度仍挂在原来的集合上。不要把 {A,B} 改成 {A}，不要重算。已删除的人不能再被选进新的日期。名单里不再出现，旧记录上可以标「已删除」。

居住日期的字段是：住所、开始日、结束日、一名或多名居住者。没有「填写人数」的输入框。人数若要显示，只作为已选人数的结果，例如选了 A 和 B 之后旁边写「2 人」。

保存时检查：

- 同一住所的日期不能重叠。重叠就拒绝，并指出已有的那一段。
- 同一个人不能在同一天属于两个住所。拒绝并指出是谁、哪一天、另一个住所。
- 两个住所在同一天分别住着不同的人，可以保存。

快捷操作只是帮用户选人和日期，例如把结束日填成今天。它不搬库存，也不把这组人自动写满以后的每一天。

删除住所要确认，并写明将删除的用品、批次、截图和居住日期。居住者名单不因删除住所而消失。取消则什么都不删。

## 5. 数据模型

**居住者：** 稳定 id、当前名字、是否已删除、删除前保留的名字。

**居住日期：** 住所、开始日、结束日（两端都算）、居住者 id 的集合。集合至少一人。身份是 id 集合，不是人数。

**住所：** 名称。

**用品：** 住所、品牌、规格、单位、快用完天数（默认 5）、快过期天数（默认 3）。同一住所内品牌 + 规格唯一。

**批次：** 用品、来源（新购或盘点盈余）、日期、原始数量、剩余、价格（分，可空）、优惠（分，可空）、渠道（可空）、到期日（可空）。

**截图：** 属于新购批次，存在应用私有目录。

**记账：** 新购、显式消耗、废弃、盘点。盘点重放时得到账面、推算消耗、盈余。消耗和废弃保存扣了哪些批次。

**设置：** 统计范围，周、月或年，默认周。

在手、速度、用完日都由记账和居住日期重算，不存成用户设置。

## 6. 四种记账

重放顺序：时间早的先算。同一天按新购、废弃、显式消耗、盘点，再按保存顺序。

先到期先出：到期日早的先扣，没有到期日的最后，到期日相同则更早的购买先扣。

**新购**增加批次和在手，价格图增加一点，不产生消耗。

**显式消耗**减少在手。日期落在该住所的某个集合上时，整笔数量属于那个集合。

**废弃**减少在手，不进速度。

**盘点：** 账面 = 重放到达这次盘点之前的在手。推算消耗 = max(0, 账面 − 实盘)。盈余 = max(0, 实盘 − 账面)。推算消耗按先到期先出扣批次。盈余生成没有价格、渠道、到期日和截图的批次。

推算消耗的日期范围：上一次盘点日的下一天，到本次盘点日，两端都算。若从未盘点，则从第一笔新购的日期算到本次盘点日，两端都算。只统计这个住所有人的日子。人在别的住所、或这一天这个住所没有人，都不进入这包货的分母。集合不同就按集合拆开。

显式消耗的日子从这段的天数里拿掉，因为它已经整笔归了那天的集合。废弃不进入这段数量。

## 7. 后台的四种算法

以下内容只给实现看。界面不出现这些名字。

一个情况 s =（住所，居住者 id 集合）。下面的「天数」都是该住所、该集合出现的日历日个数。另一住所的日子不进这个住所的分母。

一条观测是一段有总数量 Q 的消耗：一次盘点推算出的数量，或「买下到用完」这种没有逐日记录的跨度。显式消耗不放进 Q。

### 方案 1：整段只有一个集合

整段都是同一个 s。s 得到全部 Q。日速度 = Q / 天数。权重 = 这种整段里的天数。

### 方案 2：按天数分

一段里有多个集合。每个集合分到 q_s = Q × d_s / Σd。星期一到星期日若是 5 天和 2 天，就是 5/7 和 2/7。每个集合的日速度都是 Q / Σd，所以这一步假定每天用得一样多。权重 = 这种混合段里的天数。

回看里同类混合若始终是同一种天数比例，就停在这一步。把同样的 5 天 {A}、2 天 {A,B} 再重复多少周，都解不出两组不同的日速度，偏差还在。这句话写在设计里，不要写进界面。

### 方案 3：不同的天数组合

只有当同一组互相一起出现过的集合，在回看里至少有两种不同的天数组合，并且未知数不超过两个、方程分得开时，才启用。

对每一条观测 i，设两个集合的天数是 d_i、e_i，数量是 Q_i：

- Sdd = Σ d_i²，See = Σ e_i²，Sde = Σ d_i e_i
- Td = Σ d_i Q_i，Te = Σ e_i Q_i
- Δ = Sdd × See − Sde²

Δ = 0 时分不开，本方案权重为 0，这些观测退回方案 1 或方案 2。

分得开时：

- r_d = (Td × See − Te × Sde) / Δ
- r_e = (Te × Sdd − Td × Sde) / Δ

若其中一个小于 0，把它改为 0，另一个用一维最小二乘重算：r = Σ(天数 × Q) / Σ(天数²)，分母为 0 则速度为 0。两个都小于 0，则都为 0。

然后每条观测再分一次，使各份加总仍等于 Q：q_s = Q × (d_s × r_s) / Σ(d × r)。分母为 0 时退回按天数分。

权重 = 这些分得开的观测里的天数。此时方案 1 和方案 2 对同一批观测的权重改为 0，避免有偏的「每天一样」再把分开的速度拉回去。

出现第三个互相耦合的集合时，不要上通用求解器。这组观测退回方案 1 和方案 2，方案 3 权重为 0。

彼此没有出现在同一段里的集合，分开处理。{B} 的一整周不能用来拆 {A} 和 {A,B}，也不能收到 {A} 的速度。

### 方案 4：记了具体某一天

显式消耗整笔属于那一天的集合。日速度就是那天的数量（多天则是这些天的数量之和除以天数）。权重 = 有显式消耗的天数。这些天不再参加方案 1 到 3 的分母。

### 合并

某个集合的日速度 = 各方案为它给出的日速度的加权平均，权重用上面的天数。某个方案没有为它给出速度，就不进平均。算完即用，不展示。

## 8. 往前走

从今天开始，剩余 = 在手。某一天的集合：

1. 该住所已有写明的居住日期盖住这一天：用那组人。
2. 否则看该住所最近 7 天里同一个星期几。有人就用那天的集合，没有人就不减。
3. 这个 7 天模板不随统计范围变成 30 天或 365 天。

人在这个住所：减去该集合的合并日速度。速度未知就停住，首页的速度和用完时间都是「无法估算」，不要换一组人，不要除以人数，不要用成员的速度拼出来。速度为 0 则这一天不减，继续走。剩余减到 0 的时刻就是用完时间；若正好用完整数天，用完时间是最后那天的次日 0 点。

首页速度 = 在手 / 从现在到用完的天数。在手为 0 时，用完时间是「已经用完」。

## 9. 数值例子

居住者就叫 A 和 B。住所「家」。用品是一包日用品，单位「包」。快用完 5 天，快过期 3 天。下面的分数是实现要断言的内部结果。界面上不要出现。

### 9.1 周一买下，周日用完

现在先看成 2026-05-11。上一周是 2026-05-04（周一）到 2026-05-10（周日），共 7 天，都在「家」：

- 周一到周五：{A}，5 天
- 周六到周日：{A,B}，2 天

2026-05-04 新购 2 包。优惠前总价 20 元，优惠 0，渠道超市，到期 2026-06-30。实付单价 10 元/包。

2026-05-10 点数，实盘 1 包。账面 2，推算消耗 1，盈余 0。在手变成 1。没有显式消耗，没有废弃。

这一包的 1，按方案 2 分：

- {A} 得到 5/7 包
- {A,B} 得到 2/7 包

两边的日速度都是 1/7 包/天。方案 3 的权重是 0，因为只有这一种 5+2 的组合。再重复几个同样的星期，权重仍是 0。

默认统计范围是周，这 7 天都在里面。未来没另写日期，所以下一周仍是周一到周五 {A}、周末 {A,B}。两组日速度相同，每天减 1/7 包。在手 1 包，用完时间是 2026-05-18 00:00。首页速度 = 1 / 7 = 1/7 包/天。

用户看到的是：在手 1 包，速度 1/7 包/天，用完 2026-05-18。看不到 5/7 和 2/7。

今天 05-11 加 5 天是 05-16。用完日 05-18 更晚，默认快用完列表没有这条。

### 9.2 后面一整周只有 {B}

2026-05-11 到 2026-05-17 这 7 天，家里只有 {B}。2026-05-17 点数，实盘 3/10 包。账面是 1，推算消耗 7/10，在手变成 3/10。

{B} 是整段一个集合，方案 1：日速度 = (7/10) / 7 = 1/10 包/天。

这不是 {A} 的 1/7。不能因为都是一个人就抄 {A}。{A,B} 的速度也不能拿来除以 2 当作 {B}。这一周也拆不开 {A} 和 {A,B}，方案 3 的权重仍是 0。

把「现在」放在 2026-05-18。最近 7 天全是 {B}，没写未来日期，所以往后每一天都按 {B} 减 1/10 包。在手 3/10，用完时间是 2026-05-21 00:00。首页速度 = (3/10) / 3 = 1/10 包/天。

用户看到的是：在手 3/10 包，速度 1/10 包/天，用完 2026-05-21。看不到权重，也看不到 {A} 的 1/7。

默认周回看此时只含 {B} 这一周，速度也是 1/10。改成月回看后，{A} 的 1/7 和 {A,B} 的 1/7 仍留在后台，但 {B} 的日子还是减 1/10，不会被并成「1 个人」的一个速度。若错误地按人数合并，1 人那一档会变成 (5/7 + 7/10) / 12 = 33/280 包/天。结果不能是这个数。

05-21 ≤ 05-18 + 5 天（05-23），这条进入快用完列表。该用品的快用完天数改成 2 后，05-21 晚于 05-20，退出列表。用完时间本身不变。

到期 2026-06-30 的批次不在临期页。

### 9.3 方案 3 何时把 {A} 和 {A,B} 分开

这是另一组观测，用来锁定算法，不要和上面 {B} 的那一周混成同一条首页结果。

- 观测一：{A} 5 天，{A,B} 2 天，Q = 1 包
- 观测二：{A} 7 天，Q = 7/10 包

二元方程的解是：{A} 为 1/10 包/天，{A,B} 为 1/4 包/天。第一包被改分为 1/2 和 1/2，不再是 5/7 和 2/7。方案 3 权重是 14 天，方案 2 对这两条观测的权重变为 0。{B} 不在这组方程里，不会得到 1/10 或 1/4。

此时若在手 1 包，并且未来 7 天已经写成前 3 天 {A}、后 4 天 {A,B}：先减 3/10，剩 7/10，再按 1/4 包/天走到 2.8 天。用完时间在 5.8 天处，也就是 29/5 天。首页速度 = 5/29 包/天。用户仍只看到这一个速度和这一个用完时间。

## 10. 价格图

每个用品一张图，只含该用品的新购。横轴购买时间，纵轴实付单价。可以多选。选中后列出购买数量、优惠金额、购买价格、实付单价、渠道，并能看截图。没有购买时显示「还没有购买记录」。没有截图时显示「这笔记账没有截图」。

## 11. 快用完和快过期

| | 快用完 | 快过期 |
| --- | --- | --- |
| 看什么 | 往前走得到的用完日 | 某个批次的到期日 |
| 出现在 | 首页 | 临期页 |
| 默认 | 5 天 | 3 天 |
| 谁可以改 | 每个用品自己的天数 | 每个用品自己的天数 |
| 已经发生 | 在手为 0 也算 | 已经过期也算 |
| 粒度 | 用品 | 批次 |

两边互不牵扯。

## 12. 边界

- 消耗或废弃超过在手：拒绝。
- 优惠大于购买价格、数量不合法、渠道为空：拒绝。
- 同一住所日期重叠，或同一个人同一天出现在两个住所：拒绝，已有记录不变。
- 删除有数据的住所：必须确认。
- 重放后库存会变成负数：拒绝删除或修改。
- 截图文件丢失：该位置显示「截图文件丢失」。
- 显式消耗已经减少账面之后再盘点：推算消耗只含额外缺口。
- 废弃不进速度。
- 改统计范围后重算。星期模板仍是最近 7 天。
- 改一个用品的两个提醒天数，只影响它是否出现在首页或临期页。
- 删人或改名不重算已有集合的速度。
- 走满 366 天仍有剩余：一年内不会用完。

先到期先出的对照：甲批次到期更早、剩余 1，乙批次更晚、剩余 5。消耗 2 后甲为 0、乙为 4。同样的数量若是废弃，库存一样减，速度不变。

临期对照：剩余大于 0 且两天后到期，默认 3 天要出现；把该用品改成 1 天后不出现。已经过期且仍有剩余的，改成 1 天也出现。

## 13. 明确不做

- 账号、登录、服务器、同步
- 用人数标识情况，或把 {A} 和 {B} 当成同一种「1 人」
- 从集合里的人推速度，或把速度除以人数
- 界面展示方案、权重、5/7、2/7，或每一组人各自的速度
- 用通用优化库求解两个以上互相耦合的集合
- 把重复的 5+2 星期当成能消除按天分摊的偏差
- 住所之间调拨库存
- 把点数当成购买或当成手填消耗
- 把盘点盈余当成负消耗
- 把废弃计入速度
- 删除人之后改写历史集合或重算速度
- 系统推送、桌面小组件、条码、购物分享
- 把快用完默认做成 14 天，或把快过期默认做成 30 天
