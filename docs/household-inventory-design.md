# 家庭日用品库存 — 产品设计

本文给实现用。只描述产品、数据、计算和界面，不包含实现代码。应用是 Android 手机上的本地库存：记录日用品、记下使用、估计何时该补。无账号，无后端，数据不出这部手机。

## 1. 产品一句话

用户在一部手机上管理一个或多个住所的日用品。每个住所的库存、购买价格和使用速度完全分开。应用根据「这个住所、这组人数」自己的消耗记录，估计还要多久用完，并单独提醒快过期的批次。

## 2. 已经定下的规则

下面这些是产品决策，实现时照做，不再改口径。

1. **点数就是盘点。** 它把在手数量改成用户数到的数量。它不是购买，也不是用户手填的一笔消耗。
2. **盘点会自动算出消耗。** 账面数量已经包含上次结存之后的新购、显式消耗和废弃。推算消耗 = max(0, 账面 − 实盘)。这笔推算消耗是真实消耗，计入周、月、年速度。
3. **实盘高于账面时，多出来的是盈余调整，不是负消耗。** 盈余增加库存，不进入速度，也不出现在价格图上。
4. **显式消耗仍然保留。** 同一批数量不能算两次。显式消耗发生时已经减少账面，之后盘点的推算消耗只含还没记过的缺口。
5. **速度按情况分开。** 一个情况 = 一个住所 + 一个人数。只有这个情况生效期间发生的消耗，才进入这个情况的速度。这个情况没有消耗历史时，速度是未知。不借用另一个人数的速度，也不把速度除以人数。
6. **预测窗口是滚动时长。** 周 = 最近 7 天，月 = 最近 30 天，年 = 最近 365 天。用户选其中一个作为预测依据。另外两个只作参考，不参与预计用完日。
7. **日速度的分母是这段居住在窗口里的生效天数，不是窗口的全部天数，也不是人数。** 窗口只负责截取最近 7 / 30 / 365 天里的记录。预测要回答的是「按这种住法继续用，还要多久用完」。
8. **快用完默认 5 天，快过期默认 3 天。** 两个提醒分开。每个用品有自己的快用完天数和快过期天数，都可以改。首页用该用品的快用完天数；临期页用该用品的快过期天数。
9. **同一住所里，品牌 + 规格相同的购买归入同一个用品。** 价格图是这个用品在这个住所的购买历史。另一个住所里同名同规格是另一个用品。
10. **实付单价 = (购买价格 − 优惠金额) / 数量。** 购买价格是优惠前总价，不是单价。价格图画实付单价。选中购买点时显示购买数量、优惠金额、购买价格、实付单价、渠道。
11. **在手数量 = 各批次剩余之和。** 每次新购是一个批次，自带到期日、价格和截图。扣减默认先到期先出（没有到期日的批次最后扣）。消耗和废弃都减少库存；废弃不计入速度。盘点推算出来的消耗计入速度。
12. **居住区间不能重叠。** 任一时刻最多一个住所在生效。重叠是错误，用户必须自己改，应用不自动截断、不自动合并。
13. **删除住所必须确认。** 确认文案写明该住所的库存、批次、照片和历史会被永久删除，并且不会转到别的住所。禁止静默删除库存。
14. **截图留在那一笔购买上。** 可以从该用品的价格历史打开。
15. **住所之间不调拨库存。** 没有「把这提纸搬到另一个住所」的操作。

补充约定（实现需要一个明确口径）：

- 界面语言是中文。金额是人民币，存储用分，界面显示元，保留两位小数。数量用十进制，最多三位小数，内部不要用二进制浮点做加减。
- 每个用品有计量单位（提、卷、瓶……）。同一用品的购买、消耗、废弃、盘点都用这个单位。
- 预测窗口是全应用一个设置，默认「月」。不是每个用品各选一个窗口。
- 提醒只出现在应用里的首页和临期页，不发系统通知。
- 不做云备份，不做账号，不做导出。卸载应用后本地数据和照片一起消失。
- 不预置示例商品。
- 新购的数量一旦保存就不变。价格、优惠、渠道、到期日和截图可以以后改。消耗、废弃、盘点、新购都可以删除；删除后按时间顺序重算库存和速度，不能把库存算成负数。删不掉时告诉用户哪笔记账挡住了它。
- 查看某个住所时，如果它正是当前生效住所，预测用当前人数。如果不是，用该住所最近一段居住区间的人数。该人数没有消耗历史，就显示未知。

## 3. 导航

底部三个入口：

- **首页**：现在该补什么。
- **临期**：哪些批次快过期。
- **住所**：住所和居住区间。

首页进入「库存列表」，库存列表进入「用品详情」。四种记账（新购、点数、消耗、废弃）从首页进入，详情页里也可以进入。它们是独立的全屏表单。

顶部始终标明正在查看的住所。切换查看的住所只改变列表，不改变当前生效的居住区间，也不搬运库存。

```
首页
  ├─ 快用完列表 → 用品详情
  ├─ 新购 / 点数 / 消耗 / 废弃
  └─ 全部库存
        └─ 用品详情
              ├─ 价格图与截图
              ├─ 批次
              └─ 修改两个提醒天数
临期
  └─ 批次行 → 用品详情
住所
  ├─ 新增 / 删除住所
  └─ 居住区间（含快速设置）
```

查看住所与库存列表、临期列表绑定：看「家」时，不出现「父母家」的用品或批次。没有「全部住所混在一起」的列表。

## 4. 页面

### 4.1 首页

首页回答「这个住所里，哪些用品快用完了，何时用完」。

顶栏：正在查看的住所。旁边用一行小字写当前预测情况，例如「按 家 · 4人 估算」。如果查看的不是当前生效住所，写「当前人在另一住所；这里按最近一次 父母家 · 2人 估算」。

快用完列表的每一行：

- 品牌、规格
- 在手数量和单位
- 作为预测依据的那个速度（例如「月 0.15 提/天」）
- 另外两个窗口的速度，字小一些，标明「参考」
- 预计用完日期，以及大约还有几天
- 该用品自己的快用完天数（例如「5 天内提醒」）

列入条件（满足任一即可）：

- 在手数量为 0
- 当前情况在所选窗口上有正的日速度，且 在手 / 日速度 ≤ 该用品的快用完天数

排序：在手为 0 的在前，其余按预计天数从短到长，再按名称。

快捷按钮四个：**新购**、**点数**、**消耗**、**废弃**。表单默认带上正在查看的住所，用品选择器只列出这个住所的用品。

「全部库存」进入库存列表。

空状态：

- 还没有任何住所：说明需要先建住所并写下人数，按钮去住所页。
- 有住所但没有用品：说明这里还没有日用品，按钮去新购。
- 有用品但没有达到快用完：说明按各用品自己的快用完天数，目前没有要补的。不把库存列表塞进首页。

速度未知且在手大于 0 的用品不进快用完列表。在手为 0 的仍然进，速度位置写「未知」。

### 4.2 库存列表

只显示正在查看的住所。

每行：品牌、规格、在手数量、预计用完（日期，或「未知」，或「当前窗口没有消耗」）。

默认按预计用完从早到晚排，未知和「没有消耗」排在后面。提供按品牌、规格的本地搜索。

空状态与首页「还没有用品」相同。

### 4.3 用品详情

- 品牌、规格、单位、所属住所、在手数量
- 预测情况，例如「家 · 4人」
- 三行速度：周、月、年。全应用选中的那个窗口标「预测依据」。另外两行标「参考」
- 预计用完日。只由「预测依据」那一行决定
- 一句说明：其他人数的速度另行计算，不参与这次预计，也不按人头折算
- 两个可编辑数字：快用完天数、快过期天数。新建用品分别是 5 和 3。允许 0 到 365 的整数。0 表示只在已经用完，或已经到期（含今天）时提醒
- 价格折线图和选中点明细
- 批次列表：剩余、到期日、来源（新购或盘点盈余）、渠道（盈余批次没有渠道）
- 四个记账入口

速度未知时，不显示一个假的用完日，文案是：「家 · 4人 还没有消耗记录，无法估算。不会用其他人数的速度代替。」

### 4.4 新购

字段：

- 住所（默认正在查看的住所）
- 品牌、规格、单位。若该住所已有相同品牌 + 规格（去掉首尾空白后比较），归入原用品，不新建。单位沿用原用品
- 数量，必须大于 0
- 购买价格：优惠前总价，大于等于 0
- 优惠金额：大于等于 0，且不能大于购买价格
- 渠道，必填
- 购买时间，默认现在
- 到期日，可空
- 截图，可零张或多张

表单实时显示实付单价。保存后增加一个批次，在手增加，价格图增加一个点。新购不是消耗。

### 4.5 点数（盘点）

字段：用品、实盘数量（大于等于 0）、盘点时间（默认现在）。

打开时显示账面数量。提交前根据差额给出预览，且两种结果不会同时出现：

- 实盘 < 账面：将记入推算消耗 = 账面 − 实盘。写明这笔会计入使用速度，并按「上次结存到这次盘点」之间、本住所实际居住的人数分摊
- 实盘 > 账面：将记入盈余调整 = 实盘 − 账面。写明这不是购买、不是负消耗、不计入速度、不进入价格图
- 相等：库存不变，不产生消耗，也不产生盈余

预览里同时写明：「已经记过的消耗和废弃已在账面里，不会再算一次。」

### 4.6 消耗

字段：用品、数量（大于 0）、发生时间（默认现在）。

按先到期先出减少批次。数量大于在手时拒绝，库存不能变成负数。

这笔是显式消耗，计入发生时刻所属的居住情况。发生时刻没有落在本住所的任何居住区间时，仍然扣库存，但这笔不进入任何速度，表单上先警告。

### 4.7 废弃

字段与消耗相同，另加一个可空的原因。

同样先到期先出，库存不足就拒绝。废弃减少在手，**不计入**任何速度。

### 4.8 临期

只显示正在查看的住所。一行是一个批次，不是一个用品。

列入条件同时满足：

- 剩余数量大于 0
- 有到期日
- 到期日 ≤ 今天 + 该用品的快过期天数

已经过期的批次满足第三条。没有到期日的批次永不出现。剩余为 0 的不出现。

每行：品牌规格、剩余数量、到期日、「已过期 N 天」或「N 天后过期」、渠道、该用品的快过期天数。

排序：已过期的在前（过期更久的更前），其余按到期日从早到晚。

页顶说明：这里只看到期，不看用得快不快。默认 3 天，每个用品可以自己改。

空状态：按各用品自己的快过期天数，没有即将到期或已经过期的批次。

一个用品可以只出现在首页、只出现在临期页、两边都出现，或两边都不出现。

### 4.9 住所

住所列表显示名称、用品个数。可以新增和删除。

新增只需要名称。名称去掉首尾空白后不能为空，也不能与已有住所重名。

删除弹出确认框，写明将永久删除的用品数、批次数、截图数，以及消耗、废弃、盘点和居住区间。写明库存不会转移到其他住所。用户取消则什么都不删。确认后才删除。删除当前生效住所后，不自动改选另一个住所。

居住区间是全局时间线，因为任意住所的区间都不能互相重叠。每段显示：住所、人数、开始、结束（或「至今」）。

快速设置的字段：住所、人数（大于等于 1 的整数）、开始时间、结束时间。结束可以选「至今」。

保存时若与任何已有区间有交集，拒绝保存，并指出冲突的那一段。应用不悄悄改旧区间。首尾相接不算重叠：上一段在某个时刻结束，下一段在同一时刻开始，可以。

另外提供「从现在起改为……」：把覆盖现在的那段的结束时间改成现在，再开一段从现在开始、结束为「至今」的新区间。这一步是一次保存；若新区间会与其他区间重叠，整步取消，原来的区间保持原样。它只改变「人住在哪、有几个人」，不移动库存。

没有居住区间时，库存仍然可以记。速度显示未知，住所页提示先补区间。补上或改过区间之后，速度按新区间重算。

## 5. 数据模型

逻辑上有这些东西。名称用中文，实现时可以另取英文表名。

**住所**

- 名称
- 创建时间

**居住区间**

- 所属住所
- 人数
- 开始时刻（含）
- 结束时刻（不含）；空表示至今

任意两段的时间不能有交集，不论是不是同一个住所。

**用品**

- 所属住所
- 品牌、规格、单位
- 快用完天数，默认 5
- 快过期天数，默认 3

唯一性：同一住所内，品牌 + 规格唯一。

**批次**

- 所属用品
- 来源：新购，或盘点盈余
- 购入或调整的时刻
- 原始数量、剩余数量
- 购买价格（分）、优惠金额（分）；盈余批次这两项为空
- 渠道；盈余批次为空
- 到期日，可空

**购买截图**

- 所属新购批次
- 应用私有目录中的相对路径
- 排序

**记账事件**（按时间重放）

- 类型：新购、显式消耗、废弃、盘点
- 所属用品（从而属于唯一住所）
- 发生时刻
- 新购：数量、价格、优惠、渠道、到期日，并产生批次
- 显式消耗：数量；保存扣了哪些批次、各扣多少
- 废弃：数量、可空原因；同样保存批次分配
- 盘点：实盘数量；重放时算出账面、推算消耗、盈余

**应用设置**

- 预测窗口：周、月或年，默认月

在手数量和速度不单独当作无法追溯的事实。它们由事件和居住区间重算得到。批次剩余是重放的结果。

## 6. 四种记账怎么影响库存和速度

重放顺序：发生时刻早的先算。同一时刻按新购、废弃、显式消耗、盘点，再按保存顺序。

扣减顺序（消耗、废弃、盘点推算消耗都一样）：剩余大于 0 的批次里，到期日早的先扣；没有到期日的排在最后；到期日相同则购入更早的先扣。

### 新购

新建或并入用品，新增批次，剩余等于购买数量。在手增加。价格图多一个点。截图挂在这个批次上。不产生消耗。

### 显式消耗

减少在手，并计入发生时刻那一段居住情况的速度。必须是本住所的居住区间。扣减分配要保存下来，供删除后重放。

### 废弃

减少在手。不进入速度。

### 点数（盘点）

设账面 = 这次盘点重放之前的在手数量。账面已经包含上次结存以来的新购、显式消耗、废弃，以及更早的盘点结果。

- 推算消耗 = max(0, 账面 − 实盘)
- 盈余 = max(0, 实盘 − 账面)

推算消耗大于 0 时，按先到期先出从批次扣掉同样的数量，使剩余之和等于实盘。这笔数量是消耗，进入速度。

盈余大于 0 时，新增一个「盘点盈余」批次，数量和剩余都等于盈余，没有价格、渠道、到期日和截图。它以后可以被消耗或废弃扣掉。它不是购买。

推算消耗在时间上的归属：

- 基准时刻：上一笔盘点的时刻；如果从未盘点过，则是该用品第一笔新购的时刻
- 分摊区间：(基准时刻, 本次盘点时刻]
- 把推算消耗按时间均匀分到这个区间
- 只把落在**本住所**居住区间上的部分，分给对应的人数。同一区间里人数变过，就按各段时长拆开，分别进入「住所 + 人数」
- 落在其他住所，或没有居住区间的时间上的部分，是未归属消耗：库存已经按实盘改过，但这部分不进入任何情况的速度
- 区间时长为 0 时，若盘点时刻正好落在本住所的某段居住上，全部计入那个情况；否则未归属
- 分摊用整数毫单位，最后一段吃掉余数，各段之和必须等于推算消耗

未归属不是把速度除以人数，也不是记到另一个住所。用品详情如果存在未归属消耗，提示用户补全这个住所的居住区间；区间补上后重算，消耗会进入正确的情况。

## 7. 速度和预计用完

一个情况 S =（住所，人数）。只统计用品属于该住所、且归属到 S 的消耗。

消耗量(S, 窗口) = 窗口内的显式消耗 + 窗口内分摊到的推算消耗

废弃不加入。盈余不加入。其他人数的消耗不加入。其他住所的消耗不加入。

窗口是半开区间 [现在 − D, 现在)，D 为 7、30 或 365 天，按精确时长，不按日历上的「本周」「本月」。

生效时长 = S 的居住区间与这个窗口的交集。

日速度：

- S 从未有过大于 0 的显式消耗或推算消耗：**未知**
- 交集时长为 0：**不适用**（这几天不是这种住法）
- 交集时长大于 0，消耗量为 0，但 S 以前有过消耗：**0**
- 其他：消耗量 / 交集天数

预计用完只看用户选中的窗口：

- 日速度未知或不适用：预计用完未知
- 日速度为 0：当前窗口没有消耗，不估日期
- 日速度大于 0：预计天数 = 在手 / 日速度，用完时刻 = 现在 + 预计天数

快用完：在手为 0，或者日速度大于 0 且预计天数 ≤ 该用品的快用完天数。默认阈值是 5，不是全应用锁死，用品可以改。

### 7.1 数值例子

把「现在」冻结在 2026-05-01 00:00。区间都是含起点、不含终点。

住所「家」。用品：清风，130抽×6，单位「提」。快用完 5 天，快过期 3 天。预测依据是月。

居住：

- 家 · 2人：[2026-04-01, 2026-04-11)，10 天
- 家 · 4人：[2026-04-11, 2026-05-01)，20 天，当前生效

记账：

| 时刻 | 事件 | 库存结果 |
| --- | --- | --- |
| 04-01 | 新购 10 提。优惠前总价 100 元，优惠 10 元，渠道超市，到期 06-30。实付单价 9 元/提 | 批次 A 剩余 10。账面 10 |
| 04-05 | 显式消耗 2 提。当时是 2 人 | A 剩余 8。账面 8。这 2 提计入家·2人 |
| 04-08 | 废弃 1 提 | A 剩余 7。账面 7。不计入速度 |
| 04-10 | 点数，实盘 5 | 账面 7。推算消耗 2。盈余 0。A 剩余 5 |
| 04-20 | 新购 6 提。优惠前总价 66 元，优惠 6 元，渠道线上，到期 05-03。实付单价 10 元/提 | 批次 B 剩余 6。账面 11 |
| 04-25 | 显式消耗 3 提。当时是 4 人 | 先扣 B（05-03 早于 06-30）。B 剩余 3，A 剩余 5。账面 8。这 3 提计入家·4人 |
| 04-30 | 点数，实盘 10 | 账面 8。推算消耗 0。盈余 2。批次 C 剩余 2，无价格、无到期。账面 10 |

04-10 的推算消耗 2 提：基准是 04-01 的第一笔新购，分摊区间 9 天，全部落在家·2人。所以家·2人得到这 2 提。04-05 那笔显式消耗 2 提已经从账面里去掉了，不在这 2 提里面。家·2人的消耗合计是 4 提，不是 6 提。废弃的 1 提不在其中。核对：10 − 2 − 1 − 2 = 5，与实盘一致。

04-30 实盘比账面多 2，只做盈余调整。速度不减少，价格图不加这个点。

速度（现在 = 2026-05-01 00:00）：

家·2人有消耗历史（4 提）。

- 周 [04-24, 05-01)：生效 0 天。不适用
- 月 [04-01, 05-01)：生效 10 天，消耗 4 提。日速度 4/10 = 0.4 提/天
- 年：同样是 0.4 提/天

家·4人有消耗历史（3 提）。这是当前预测情况。

- 周：生效 7 天，消耗 3 提。日速度 3/7 提/天
- 月：生效 20 天，消耗 3 提。日速度 3/20 = 0.15 提/天。分母不是 30，也不是 20×4
- 年：同样 0.15 提/天

预测依据是月，所以预计天数 = 10 / 0.15 = 66 天又 16 小时，用完时刻 2026-07-06 16:00。周速度和年速度只显示为参考。66 天多大于该用品的 5 天，在手也不是 0，首页快用完列表没有这条。

价格图只有两个点：04-01 的 9 元/提，04-20 的 10 元/提。批次 C 不在图上。

临期：今天是 2026-05-01。批次 B 剩余 3，到期 05-03，距离 2 天，不超过该用品的 3 天，出现在临期页。批次 A 到期 06-30，不出现。批次 C 没有到期日，不出现。

把这个用品的快过期天数改成 1 后，批次 B 不再出现（2 天 > 1 天）。把快用完天数改成 80 后，这条才会因为 66.7 ≤ 80 出现在首页。两个改动互不影响。

再设一个用品只用来核对默认 5 天：在手 2 个，当前情况的预测日速度是 1 个/天，预计 2 天。2 ≤ 5，出现在首页。把该用品快用完天数改为 1 后不再出现。在手改为 0 后，即使速度未知也出现在首页。

## 8. 价格图

每个用品一张图，只含该用品的新购批次。横轴是购买时间，纵轴是实付单价。一个点也要能看见；没有购买时显示「还没有购买记录」。

点按选中，再点取消，可以同时选多个。选中的点高亮。未选时，图下写「点选一个或多个购买点」。选中后按时间列出，每一笔显示：

- 购买时间
- 购买数量
- 优惠金额
- 购买价格（优惠前总价）
- 实付单价
- 渠道
- 查看截图；没有截图时写「这笔记账没有截图」

截图全屏看，同一笔有多张时可以左右切换。截图不能从别的用品或别的住所打开。

## 9. 快用完和快过期

| | 快用完 | 快过期 |
| --- | --- | --- |
| 看什么 | 在手还能用多久 | 某个批次的到期日 |
| 出现在 | 首页 | 临期页 |
| 默认 | 5 天 | 3 天 |
| 谁可以改 | 每个用品自己的快用完天数 | 每个用品自己的快过期天数 |
| 已经发生 | 在手为 0 也算 | 已经过期也算 |
| 粒度 | 用品 | 批次 |

首页不因为快过期而把用品列进来。临期页不因为快用完而把批次列进来。

## 10. 空状态、拒绝和边界

- 消耗或废弃超过在手：拒绝，在手不变。
- 新购数量 ≤ 0、盘点数量 < 0、优惠为负、优惠大于购买价格、渠道为空：拒绝。
- 实付单价的分母不会是 0，因为数量必须大于 0。
- 居住区间重叠：拒绝，并指出冲突段。
- 删除有数据的住所：必须经过写明后果的确认。
- 重放后会把某笔消耗扣成负数：拒绝这次删除或修改，并说明依赖它的记账。
- 文件丢了：价格历史里该张图的位置显示「截图文件丢失」，其余记账还在。
- 同一用品同时快用完又有批次快过期：两个页面都出现。
- 速度未知且在手大于 0：不进首页快用完。
- 先记了显式消耗再盘点：推算消耗只含额外缺口。
- 改预测窗口：用完日立刻只跟新窗口走；另外两个窗口仍显示。
- 改一个用品的两个天数：只影响这个用品在首页和临期页的出现，不影响别的用品，也不影响速度本身。

## 11. 明确不做

- 账号、登录、服务器、同步
- 按人数折算速度，或用另一个人数的速度填空
- 住所之间自动或手动调拨库存
- 把点数当成购买或当成用户手填的消耗
- 把盘点盈余当成负的消耗
- 把废弃计入速度
- 系统推送、桌面小组件、条码、购物分享
- 把快用完默认做成 14 天，或把快过期默认做成 30 天
