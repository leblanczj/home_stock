# 家庭日用品库存 — 产品设计

本文给实现用。只描述产品、数据、计算和界面，不包含实现代码。应用是 Android 手机上的本地库存：记录日用品、记下使用、估计何时该补。无账号，无后端，数据不出这部手机。

## 1. 产品一句话

用户在一部手机上管理一个或多个住所的日用品。每个住所的库存、购买价格和使用速度完全分开。速度按「住所 + 人数」分别测量。用完日不假设当前人数会一直持续，而是按未来每一天的住法往前减，直到在手减到 0。快过期单独提醒。

## 2. 已经定下的规则

下面这些是产品决策，实现时照做，不再改口径。

1. **点数就是盘点。** 它把在手数量改成用户数到的数量。它不是购买，也不是用户手填的一笔消耗。
2. **盘点会自动算出消耗。** 账面数量已经包含上次结存之后的新购、显式消耗和废弃。推算消耗 = max(0, 账面 − 实盘)。这笔推算消耗是真实消耗，计入周、月、年的速度测量。
3. **实盘高于账面时，多出来的是盈余调整，不是负消耗。** 盈余增加库存，不进入速度，也不出现在价格图上。
4. **显式消耗仍然保留。** 同一批数量不能算两次。显式消耗发生时已经减少账面，之后盘点的推算消耗只含还没记过的缺口。
5. **速度按情况分开。** 一个情况 = 一个住所 + 一个人数。只有这个情况生效期间发生的消耗，才进入这个情况的速度。这个情况没有消耗历史时，速度是未知。不借用另一个人数的速度，也不把速度除以人数。
6. **周、月、年只负责回看，用来测量每种情况自己的日速度。** 周 = 最近 7 天，月 = 最近 30 天，年 = 最近 365 天。全应用只选一个，默认是周。回看不表示这段时间里住法不变，也不表示未来会维持同一种住法。
7. **日速度 = 该情况在回看里的消耗量 / 该情况在回看里的生效天数。** 分母不是整段 7 / 30 / 365 天，也不是人数。回看里没有生效过的情况，这个回看下显示不适用。
8. **用完日是往前走出来的，不是「在手 / 当前日速度」。** 从该用品所在住所的在手数量出发，按未来每一天的住法往下减。某一天若已有用户写下的居住区间，用那段；没写的日子，按最近 7 天的星期重复：未来的周一用最近一个周一的住所和人数。人在这个用品的住所时，减去这一天对应情况的日速度；人在别的住所时，这个用品的库存不减。减到 0 的那一天就是用完时间。走到某天时，需要的情况速度是未知，则用完日未知，并写明缺的是哪一个情况。
9. **星期重复始终看最近 7 天。** 即使用户把速度回看改成月或年，未来没写下的日子仍按最近 7 天重复，不会按 30 天或 365 天重复。
10. **快用完默认 5 天，快过期默认 3 天。** 两个提醒分开。每个用品有自己的快用完天数和快过期天数，都可以改。首页用该用品的快用完天数；临期页用该用品的快过期天数。
11. **同一住所里，品牌 + 规格相同的购买归入同一个用品。** 价格图是这个用品在这个住所的购买历史。另一个住所里同名同规格是另一个用品。
12. **实付单价 = (购买价格 − 优惠金额) / 数量。** 购买价格是优惠前总价，不是单价。价格图画实付单价。选中购买点时显示购买数量、优惠金额、购买价格、实付单价、渠道。
13. **在手数量 = 各批次剩余之和。** 每次新购是一个批次，自带到期日、价格和截图。扣减默认先到期先出（没有到期日的批次最后扣）。消耗和废弃都减少库存；废弃不计入速度。盘点推算出来的消耗计入速度。
14. **居住区间不能重叠。** 任一时刻最多一个住所在生效。重叠是错误，用户必须自己改，应用不自动截断、不自动合并。
15. **删除住所必须确认。** 确认文案写明该住所的库存、批次、照片和历史会被永久删除，并且不会转到别的住所。禁止静默删除库存。
16. **截图留在那一笔购买上。** 可以从该用品的价格历史打开。
17. **住所之间不调拨库存。** 没有「把这提纸搬到另一个住所」的操作。人去了别的住所，只是这个住所的用品在那些天不被减库存。

补充约定（实现需要一个明确口径）：

- 界面语言是中文。金额是人民币，存储用分，界面显示元，保留两位小数。数量用十进制，最多三位小数，内部不要用二进制浮点做加减。
- 每个用品有计量单位（提、卷、瓶……）。同一用品的购买、消耗、废弃、盘点都用这个单位。
- 速度回看是全应用一个设置，默认「周」。不是每个用品各选一个回看。
- 结束为「至今」的居住区间只覆盖到现在。它不把当前人数铺进未来。用户若知道将来某几天的住法，把那段的结束时间写到将来；往前走时，写下的区间优先于星期重复。
- 提醒只出现在应用里的首页和临期页，不发系统通知。
- 不做云备份，不做账号，不做导出。卸载应用后本地数据和照片一起消失。
- 不预置示例商品。往前走时也不臆造未来的购买。
- 新购的数量一旦保存就不变。价格、优惠、渠道、到期日和截图可以以后改。消耗、废弃、盘点、新购都可以删除；删除后按时间顺序重算库存和速度，不能把库存算成负数。删不掉时告诉用户哪笔记账挡住了它。
- 往前走最多 366 天。到那时在手仍大于 0，显示「一年内不会用完」，不要无限循环。

## 3. 导航

底部三个入口：

- **首页**：现在该补什么。
- **临期**：哪些批次快过期。
- **住所**：住所和居住区间。

首页进入「库存列表」，库存列表进入「用品详情」。四种记账（新购、点数、消耗、废弃）从首页进入，详情页里也可以进入。它们是独立的全屏表单。

顶部始终标明正在查看的住所。切换查看的住所只改变列表，不改变当前生效的居住区间，也不搬运库存。

```
首页
  ├─ 快用完列表 → 用品详情
  ├─ 新购 / 点数 / 消耗 / 废弃
  └─ 全部库存
        └─ 用品详情
              ├─ 价格图与截图
              ├─ 各情况速度与往前走的日程
              ├─ 批次
              └─ 修改两个提醒天数
临期
  └─ 批次行 → 用品详情
住所
  ├─ 新增 / 删除住所
  └─ 居住区间（含快速设置）
```

查看住所与库存列表、临期列表绑定：看「家」时，不出现「父母家」的用品或批次。没有「全部住所混在一起」的列表。

## 4. 页面

### 4.1 首页

首页回答「这个住所里，哪些用品快用完了，何时用完」。

顶栏：正在查看的住所。旁边一行小字说明速度怎么测、未来怎么走，例如「速度按最近 7 天测算。没写下的未来，按最近 7 天的星期重复。」

快用完列表的每一行：

- 品牌、规格
- 在手数量和单位
- 往前走里实际用到的每一种情况，各自的日速度。例如「家·1人 1 提/天」「家·2人 2 提/天」
- 混合节奏：在手数量 / 从现在到用完时刻的天数，以及这是由哪些天拼出来的
- 用完时刻
- 该用品自己的快用完天数（例如「5 天内提醒」）

速度用当前选中的回看。另外两个回看不放在这一行，放到用品详情里作参考。

列入条件（满足任一即可）：

- 在手数量为 0
- 用完时刻已经算出来，且用完日的日期 ≤ 今天 + 该用品的快用完天数

用完日未知时，只要在手大于 0，就不进这个列表。在手为 0 的仍然进，用完位置写「已经用完」。

排序：在手为 0 的在前，其余按用完时刻从早到晚，再按名称。

快捷按钮四个：**新购**、**点数**、**消耗**、**废弃**。表单默认带上正在查看的住所，用品选择器只列出这个住所的用品。

「全部库存」进入库存列表。

空状态：

- 还没有任何住所：说明需要先建住所并写下人数，按钮去住所页。
- 有住所但没有用品：说明这里还没有日用品，按钮去新购。
- 有用品但没有达到快用完：说明按各用品自己的快用完天数，目前没有要补的。不把库存列表塞进首页。

### 4.2 库存列表

只显示正在查看的住所。

每行：品牌、规格、在手数量、用完时刻（日期和时间，或「未知：缺 家·2人 的速度」，或「一年内不会用完」）。

默认按用完时刻从早到晚排，一年内不会用完和未知排在后面。提供按品牌、规格的本地搜索。

空状态与首页「还没有用品」相同。

### 4.3 用品详情

- 品牌、规格、单位、所属住所、在手数量
- 当前速度回看，例如「全应用正在用：周」
- 这个用品会遇到的每一种情况，各显示周、月、年三行日速度。选中的回看标「用于估算」，另外两行标「参考」
- 一句说明：速度不按人数折算，也不拿另一种人数填空
- 往前走的日程：每一段的日期、星期、住所、人数、这一段减掉多少、减完还剩多少。减到 0 的那一段标出用完时刻
- 混合节奏和用完时刻
- 若中途遇到未知速度：停在那里，写明缺的情况，例如「走到 5月9日 需要 家·2人 的速度，但这个情况没有消耗记录」
- 两个可编辑数字：快用完天数、快过期天数。新建用品分别是 5 和 3。允许 0 到 365 的整数。0 表示只在已经用完，或已经到期（含今天）时提醒
- 价格折线图和选中点明细
- 批次列表：剩余、到期日、来源（新购或盘点盈余）、渠道（盈余批次没有渠道）
- 四个记账入口

### 4.4 新购

字段：

- 住所（默认正在查看的住所）
- 品牌、规格、单位。若该住所已有相同品牌 + 规格（去掉首尾空白后比较），归入原用品，不新建。单位沿用原用品
- 数量，必须大于 0
- 购买价格：优惠前总价，大于等于 0
- 优惠金额：大于等于 0，且不能大于购买价格
- 渠道，必填
- 购买时间，默认现在
- 到期日，可空
- 截图，可零张或多张

表单实时显示实付单价。保存后增加一个批次，在手增加，价格图增加一个点。新购不是消耗。

### 4.5 点数（盘点）

字段：用品、实盘数量（大于等于 0）、盘点时间（默认现在）。

打开时显示账面数量。提交前根据差额给出预览，且两种结果不会同时出现：

- 实盘 < 账面：将记入推算消耗 = 账面 − 实盘。写明这笔会计入使用速度，并按「上次结存到这次盘点」之间、本住所实际居住的人数分摊
- 实盘 > 账面：将记入盈余调整 = 实盘 − 账面。写明这不是购买、不是负消耗、不计入速度、不进入价格图
- 相等：库存不变，不产生消耗，也不产生盈余

预览里同时写明：「已经记过的消耗和废弃已在账面里，不会再算一次。」

### 4.6 消耗

字段：用品、数量（大于 0）、发生时间（默认现在）。

按先到期先出减少批次。数量大于在手时拒绝，库存不能变成负数。

这笔是显式消耗，计入发生时刻所属的居住情况。发生时刻没有落在本住所的任何居住区间时，仍然扣库存，但这笔不进入任何速度，表单上先警告。

### 4.7 废弃

字段与消耗相同，另加一个可空的原因。

同样先到期先出，库存不足就拒绝。废弃减少在手，**不计入**任何速度。

### 4.8 临期

只显示正在查看的住所。一行是一个批次，不是一个用品。

列入条件同时满足：

- 剩余数量大于 0
- 有到期日
- 到期日 ≤ 今天 + 该用品的快过期天数

已经过期的批次满足第三条。没有到期日的批次永不出现。剩余为 0 的不出现。

每行：品牌规格、剩余数量、到期日、「已过期 N 天」或「N 天后过期」、渠道、该用品的快过期天数。

排序：已过期的在前（过期更久的更前），其余按到期日从早到晚。

页顶说明：这里只看到期，不看用得快不快。默认 3 天，每个用品可以自己改。

空状态：按各用品自己的快过期天数，没有即将到期或已经过期的批次。

一个用品可以只出现在首页、只出现在临期页、两边都出现，或两边都不出现。

### 4.9 住所

住所列表显示名称、用品个数。可以新增和删除。

新增只需要名称。名称去掉首尾空白后不能为空，也不能与已有住所重名。

删除弹出确认框，写明将永久删除的用品数、批次数、截图数，以及消耗、废弃、盘点和居住区间。写明库存不会转移到其他住所。用户取消则什么都不删。确认后才删除。删除当前生效住所后，不自动改选另一个住所。

居住区间是全局时间线，因为任意住所的区间都不能互相重叠。每段显示：住所、人数、开始、结束（或「至今」）。

快速设置的字段：住所、人数（大于等于 1 的整数）、开始时间、结束时间。结束可以选「至今」。

保存时若与任何已有区间有交集，拒绝保存，并指出冲突的那一段。应用不悄悄改旧区间。首尾相接不算重叠：上一段在某个时刻结束，下一段在同一时刻开始，可以。

另外提供「从现在起改为……」：把覆盖现在的那段的结束时间改成现在，再开一段从现在开始、结束为「至今」的新区间。这一步是一次保存；若新区间会与其他区间重叠，整步取消，原来的区间保持原样。它只改变「到现在为止人住在哪、有几个人」，不移动库存，也不把新人数自动铺满未来。

没有居住区间时，库存仍然可以记。速度显示未知，住所页提示先补区间。补上或改过区间之后，速度和用完日都重算。

页上写明：要让预测用上将来某几天的真实安排，把那一段的结束时间写到将来。只选「至今」的话，未来仍按最近 7 天的星期重复。

## 5. 数据模型

逻辑上有这些东西。名称用中文，实现时可以另取英文表名。

**住所**

- 名称
- 创建时间

**居住区间**

- 所属住所
- 人数
- 开始时刻（含）
- 结束时刻（不含）；空表示至今，预测时只覆盖到现在

任意两段的时间不能有交集，不论是不是同一个住所。

**用品**

- 所属住所
- 品牌、规格、单位
- 快用完天数，默认 5
- 快过期天数，默认 3

唯一性：同一住所内，品牌 + 规格唯一。

**批次**

- 所属用品
- 来源：新购，或盘点盈余
- 购入或调整的时刻
- 原始数量、剩余数量
- 购买价格（分）、优惠金额（分）；盈余批次这两项为空
- 渠道；盈余批次为空
- 到期日，可空

**购买截图**

- 所属新购批次
- 应用私有目录中的相对路径
- 排序

**记账事件**（按时间重放）

- 类型：新购、显式消耗、废弃、盘点
- 所属用品（从而属于唯一住所）
- 发生时刻
- 新购：数量、价格、优惠、渠道、到期日，并产生批次
- 显式消耗：数量；保存扣了哪些批次、各扣多少
- 废弃：数量、可空原因；同样保存批次分配
- 盘点：实盘数量；重放时算出账面、推算消耗、盈余

**应用设置**

- 速度回看：周、月或年，默认周

在手数量和速度不单独当作无法追溯的事实。它们由事件和居住区间重算得到。批次剩余是重放的结果。用完日由速度和未来住法再算一次，不单独存成不可更新的事实。

## 6. 四种记账怎么影响库存和速度

重放顺序：发生时刻早的先算。同一时刻按新购、废弃、显式消耗、盘点，再按保存顺序。

扣减顺序（消耗、废弃、盘点推算消耗都一样）：剩余大于 0 的批次里，到期日早的先扣；没有到期日的排在最后；到期日相同则购入更早的先扣。

### 新购

新建或并入用品，新增批次，剩余等于购买数量。在手增加。价格图多一个点。截图挂在这个批次上。不产生消耗。

### 显式消耗

减少在手，并计入发生时刻那一段居住情况的速度。必须是本住所的居住区间。扣减分配要保存下来，供删除后重放。

### 废弃

减少在手。不进入速度。

### 点数（盘点）

设账面 = 这次盘点重放之前的在手数量。账面已经包含上次结存以来的新购、显式消耗、废弃，以及更早的盘点结果。

- 推算消耗 = max(0, 账面 − 实盘)
- 盈余 = max(0, 实盘 − 账面)

推算消耗大于 0 时，按先到期先出从批次扣掉同样的数量，使剩余之和等于实盘。这笔数量是消耗，进入速度。

盈余大于 0 时，新增一个「盘点盈余」批次，数量和剩余都等于盈余，没有价格、渠道、到期日和截图。它以后可以被消耗或废弃扣掉。它不是购买。

推算消耗在时间上的归属：

- 基准时刻：上一笔盘点的时刻；如果从未盘点过，则是该用品第一笔新购的时刻
- 分摊区间：(基准时刻, 本次盘点时刻]
- 把推算消耗按时间均匀分到这个区间
- 只把落在**本住所**居住区间上的部分，分给对应的人数。同一区间里人数变过，就按各段时长拆开，分别进入「住所 + 人数」
- 落在其他住所，或没有居住区间的时间上的部分，是未归属消耗：库存已经按实盘改过，但这部分不进入任何情况的速度
- 区间时长为 0 时，若盘点时刻正好落在本住所的某段居住上，全部计入那个情况；否则未归属
- 分摊用整数毫单位，最后一段吃掉余数，各段之和必须等于推算消耗

未归属不是把速度除以人数，也不是记到另一个住所。用品详情如果存在未归属消耗，提示用户补全这个住所的居住区间；区间补上后重算，消耗会进入正确的情况。

## 7. 速度和用完日

### 7.1 测量速度

一个情况 S =（住所，人数）。只统计用品属于该住所、且归属到 S 的消耗。

消耗量(S, 回看) = 回看内的显式消耗 + 回看内分摊到的推算消耗

废弃不加入。盈余不加入。其他人数的消耗不加入。其他住所的消耗不加入。

回看是半开区间 [现在 − D, 现在)。D 为 7、30 或 365 天，按精确时长，不按日历上的「本周」「本月」。默认 D = 7。

生效时长 = S 的居住区间与这个回看的交集。

日速度：

- S 从未有过大于 0 的显式消耗或推算消耗：**未知**
- 交集时长为 0：**不适用**（这段回看里不是这种住法）
- 交集时长大于 0，消耗量为 0，但 S 以前有过消耗：**0**
- 其他：消耗量 / 交集天数

三个回看都按这个公式各自算。往前走只用用户选中的那一个回看里的日速度。另外两个只在详情里作参考。

### 7.2 往前走

从现在开始，剩余 = 该用品的在手数量。未来不发明新的购买。

决定时刻 t 的住法：

1. 若有一段居住区间满足开始 ≤ t < 结束，且结束时间是用户写下的、晚于现在的时刻，用这段。
2. 结束为「至今」的区间不覆盖 t ≥ 现在。
3. 否则把 t 映回最近 7 天：模板时刻 = 现在 − 7 天 + ((t − 现在) mod 7 天)。用模板时刻上的住所和人数。未来的周一因此用的是最近一个周一。
4. 模板时刻若没有任何居住区间，这一小段谁的库存都不减。

同一住法连续的一段，一次处理：

- 住所不是这个用品的住所：剩余不变，时间往前跳过这一段。
- 住所匹配，但该情况的日速度未知：停住。用完日未知，文案点名这个情况。不改用别的人数，不除以人数。
- 日速度为 0：剩余不变，继续走。
- 日速度大于 0：这一段若足够把剩余减到 0，用完时刻 = 段起点 + 剩余 / 日速度。减到正好 0 的时刻就是用完时刻。若不够，剩余减去 日速度 × 段的天数，再走下一段。

用完日的「日期」是用完时刻的本地日期。快用完比较的是这个日期：用完日 ≤ 今天 + 该用品的快用完天数。默认 5 天。

混合节奏 = 在手数量 / 从现在到用完时刻的天数。这个数只解释已经走出来的用完时刻，不能反过来用某一个情况的速度代替这次行走。

首页这一行要同时看见：用到的每种情况自己的日速度，以及混合节奏。

只在库存还没减到 0 之前遇到的未知速度才会挡住用完日。库存若在那之前已经到 0，后面的未知情况不影响这次结果。

### 7.3 数值例子

把「现在」冻结在 2026-05-04 00:00，本地星期一。速度回看是默认的周，也就是 [2026-04-27 00:00, 2026-05-04 00:00)。最近 7 天都在住所「家」，其中 5 天是 1 人，2 天是 2 人。未来没有另写居住区间。

居住（含起点，不含终点）：

- 家 · 1人：[2026-04-27 00:00, 2026-05-02 00:00)，星期一到星期五，5 天
- 家 · 2人：[2026-05-02 00:00, 2026-05-04 00:00)，星期六和星期日，2 天

用品：清风，130抽×6，单位「提」，属于家。快用完 5 天，快过期 3 天。

记账：

| 时刻 | 事件 | 库存结果 |
| --- | --- | --- |
| 04-27 00:00 | 新购 16 提。优惠前总价 112 元，优惠 16 元，渠道超市，到期 06-30。实付单价 (112 − 16) / 16 = 6 元/提 | 剩余 16 |
| 04-28 12:00 | 显式消耗 2 提。当时是 1 人 | 剩余 14。这 2 提计入家·1人 |
| 04-29 12:00 | 废弃 1 提 | 剩余 13。不计入速度 |
| 04-30 00:00 | 点数，实盘 10 | 账面 13。推算消耗 3。盈余 0。剩余 10 |
| 05-03 12:00 | 显式消耗 4 提。当时是 2 人 | 剩余 6。这 4 提计入家·2人 |

04-30 的推算消耗：基准是 04-27 的新购，分摊区间 3 天，全部落在家·1人。显式消耗的 2 提已经从账面去掉，不在这 3 提里面。家·1人的消耗合计是 2 + 3 = 5 提，不是 2 + 2 + 3。废弃的 1 提不在其中。核对：16 − 2 − 1 − 3 = 10。

家·2人的消耗是 4 提。没有把家·1人的消耗算进来。

日速度（周回看；月和年在这个例子里相同，因为更早没有别的消耗）：

- 家·1人：5 提 / 生效 5 天 = 1 提/天
- 家·2人：4 提 / 生效 2 天 = 2 提/天

2 人的速度是 2 提/天，不是 4 / 2 / 2。分母是住在这种人数下的 2 天，不是人数。

未来按最近 7 天重复。星期一到星期五用家·1人，每天减 1 提；星期六和星期日用家·2人，每天减 2 提。在手从 6 开始：

| 日期 | 星期 | 住法 | 段初 | 结果 |
| --- | --- | --- | --- | --- |
| 05-04 | 一 | 家·1人 | 6 | 减 1，剩 5 |
| 05-05 | 二 | 家·1人 | 5 | 减 1，剩 4 |
| 05-06 | 三 | 家·1人 | 4 | 减 1，剩 3 |
| 05-07 | 四 | 家·1人 | 3 | 减 1，剩 2 |
| 05-08 | 五 | 家·1人 | 2 | 减 1，剩 1 |
| 05-09 | 六 | 家·2人 | 1 | 当天速度 2 提，走到一半减完 |

用完时刻 = 2026-05-09 12:00。混合节奏 = 6 / 5.5 天 = 12/11 提/天。这 5.5 天是 5 天 × 1 提，加上星期六的 0.5 天 × 2 提。

首页这一行写出：家·1人 1 提/天，家·2人 2 提/天，混合节奏 12/11 提/天，用完 2026-05-09 12:00。

今天是 05-04。该用品快用完天数是 5，今天 + 5 天 = 05-09。用完日就是 05-09，列入首页。把快用完天数改成 4 后，今天 + 4 天 = 05-08，05-09 不再列入。这不改变速度，也不改变临期。

价格图只有 04-27 这一个点，6 元/提。到期 06-30 的批次不进临期页：05-04 再加 3 天是 05-07，06-30 晚于它。

另外三个对照，仍用今天 2026-05-04：

- 用户另外写下父母家 [2026-05-06, 2026-05-07)。星期三人在父母家，清风的库存那天不减。日程变成：05-04 剩 5，05-05 剩 4，05-06 仍是 4，05-07 剩 3，05-08 剩 2，05-09 的 2 提正好减完。用完时刻是 2026-05-10 00:00。混合节奏 = 6 / 6 天 = 1 提/天。
- 若家·2人没有任何消耗，速度未知。走到 05-09 仍剩 1 提，但星期六需要家·2人的速度。用完日未知，文案写「家·2人」。不能改用 1 人的 1 提/天，也不能写成 2 提除以 2 人。
- 若在手只有 5 提，而家·2人仍然未知：星期一到星期五每天减 1，到 05-09 00:00 正好用完。还没用到星期六，未知的家·2人不挡住这次用完时刻。

临期对照：另一个剩余大于 0 的批次，到期 2026-05-06。05-06 ≤ 05-04 + 3 天，出现在临期页。该用品的快过期天数改成 1 后不再出现。到期 2026-05-03 且仍有剩余的批次，即使快过期天数是 1，也出现。没有到期日的不出现。

先到期先出对照：另一个用品有甲批次到期 05-20、剩余 1，乙批次到期 06-01、剩余 5。消耗 2 后甲剩余 0、乙剩余 4。这笔若是废弃，库存同样这样减，但任何情况的速度都不变。

## 8. 价格图

每个用品一张图，只含该用品的新购批次。横轴是购买时间，纵轴是实付单价。一个点也要能看见；没有购买时显示「还没有购买记录」。

点按选中，再点取消，可以同时选多个。选中的点高亮。未选时，图下写「点选一个或多个购买点」。选中后按时间列出，每一笔显示：

- 购买时间
- 购买数量
- 优惠金额
- 购买价格（优惠前总价）
- 实付单价
- 渠道
- 查看截图；没有截图时写「这笔记账没有截图」

截图全屏看，同一笔有多张时可以左右切换。截图不能从别的用品或别的住所打开。

## 9. 快用完和快过期

| | 快用完 | 快过期 |
| --- | --- | --- |
| 看什么 | 往前走得到的用完日 | 某个批次的到期日 |
| 出现在 | 首页 | 临期页 |
| 默认 | 5 天 | 3 天 |
| 谁可以改 | 每个用品自己的快用完天数 | 每个用品自己的快过期天数 |
| 已经发生 | 在手为 0 也算 | 已经过期也算 |
| 粒度 | 用品 | 批次 |

首页不因为快过期而把用品列进来。临期页不因为快用完而把批次列进来。

## 10. 空状态、拒绝和边界

- 消耗或废弃超过在手：拒绝，在手不变。
- 新购数量 ≤ 0、盘点数量 < 0、优惠为负、优惠大于购买价格、渠道为空：拒绝。
- 实付单价的分母不会是 0，因为数量必须大于 0。
- 居住区间重叠：拒绝，并指出冲突段。
- 删除有数据的住所：必须经过写明后果的确认。
- 重放后会把某笔消耗扣成负数：拒绝这次删除或修改，并说明依赖它的记账。
- 文件丢了：价格历史里该张图的位置显示「截图文件丢失」，其余记账还在。
- 同一用品同时快用完又有批次快过期：两个页面都出现。
- 用完日未知且在手大于 0：不进首页快用完。未知文案点名缺速度的情况。
- 先记了显式消耗再盘点：推算消耗只含额外缺口。
- 改速度回看：每种情况的日速度改用新回看重算，然后重新往前走。星期重复仍是最近 7 天。
- 改一个用品的两个天数：只影响这个用品在首页和临期页的出现，不影响别的用品，也不改变走出来的用完时刻。
- 未来某一天已经写了居住区间：那天用写下的住所和人数，不用星期模板。
- 人在别的住所的日子：这个用品的剩余不变。
- 走满 366 天仍大于 0：一年内不会用完。

## 11. 明确不做

- 账号、登录、服务器、同步
- 按人数折算速度，或用另一个人数的速度填空
- 用「在手 / 当前这一种人数的日速度」直接当作用完日
- 把「至今」理解成未来每一天都保持现在的人数
- 速度回看选了月或年时，把未来按 30 天或 365 天重复
- 住所之间自动或手动调拨库存
- 把点数当成购买或当成用户手填的消耗
- 把盘点盈余当成负的消耗
- 把废弃计入速度
- 系统推送、桌面小组件、条码、购物分享
- 把快用完默认做成 14 天，或把快过期默认做成 30 天
