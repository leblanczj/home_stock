# 实现提示词：家庭日用品库存 Android 应用

把下面从「你要做的事」到文末整段复制给实现用的 AI。不要再让它写一份设计，直接做出能安装运行的应用。

---

你要做的事：在一个空的 Android 工程里实现「家庭日用品库存」手机应用，并让它真正可运行。直接写代码、界面和测试。不要再输出一份设计文档来代替应用，不要留空页面，不要用假数据充页面。

这是单用户、一部手机、本地优先。不要账号，不要登录，不要后端，不要网络同步，不要你自己发明的服务器。卸载前数据只在这台设备上。

## 技术栈（锁定）

- Kotlin
- Jetpack Compose
- Material 3
- Room
- 购买截图存在应用私有目录
- minSdk 26
- 使用当前稳定的 Compose、Room、Kotlin 版本
- 界面文案用中文
- 领域计算（库存重放、速度、往前走、提醒判定）写成不依赖界面的纯 Kotlin，并用 JVM 单元测试覆盖下文的验收数据。禁止只用二进制浮点做金额和数量加减

金额用人民币「分」（整数）。数量内部用毫单位（1 个单位 = 1000，整数），界面最多显示三位小数。

可以按你习惯拆模块，但计算必须能不启动模拟器就测。

## 产品范围

用户记录家里的日用品、购买价格和截图，记下使用，估计还要多久用完，并单独看哪些批次快过期。

可以有多个住所。每个住所的用品、批次、库存和速度完全分开，列表里永远不要混在一起。不要做库存调拨，也不要在切换住所时自动搬库存。

底部三个入口：首页、临期、住所。

- 首页：列出当前查看的住所里快用完的用品。每一行有在手、用到的每种情况自己的速度、混合节奏、用完时刻。提供新购 / 点数 / 消耗 / 废弃，并能进入全部库存
- 库存列表：该住所全部用品，进入用品详情
- 用品详情：各情况在三个回看下的速度、往前走日程、用完时刻、两个提醒天数、价格图、批次、记账入口
- 临期：该住所快过期的批次
- 住所：新增、删除、为一段时间设置住所和人数

顶栏可以切换「正在查看的住所」。这只切换列表，不修改当前生效的居住区间。

## 必须遵守的计算规则

### 点数（盘点）

界面按钮写「点数」。它的含义是盘点。

- 用户输入实盘数量，应用把在手改成这个数
- 它不是新购，也不是用户手填的一笔消耗
- 账面 = 重放完这次盘点之前的在手。账面已经包含上次结存以来的新购、显式消耗和废弃
- 推算消耗 = max(0, 账面 − 实盘)。这笔是真实消耗，计入速度
- 盈余 = max(0, 实盘 − 账面)。盈余是调整，不是负消耗，不计入速度，不进入价格图
- 推算消耗和盈余不会同时大于 0
- 显式消耗功能保留。同一批货不能算两次：显式消耗已经减少账面，推算消耗只包含还没记过的缺口
- 提交前给用户看预览：差额是推算消耗、盈余，还是没有变化

推算消耗大于 0 时，按先到期先出从批次扣减，使剩余之和等于实盘。

盈余大于 0 时，新建来源为「盘点盈余」的批次：数量等于盈余，没有购买价格、优惠、渠道、到期日、截图。

推算消耗的时间归属：

- 基准时刻 = 上一笔盘点的时刻；若没有，则是该用品第一笔新购的时刻
- 把数量均匀分到 (基准时刻, 本次盘点时刻]
- 只把落在本用品所属住所的居住区间上的部分，计入对应人数。人数中途变过，就按各段时长拆开
- 其他住所或没有居住区间的时间，对应数量记为未归属：库存已按实盘改掉，但不进入任何速度。不要把这部分除以人数，不要记到别的住所
- 时长为 0 时，盘点时刻落在本住所的居住区间上，就全部计入那个情况；否则未归属
- 用毫单位，最后一段加上余数，各段之和等于推算消耗

### 速度回看

一个情况 = 住所 + 人数。只统计这个情况下的显式消耗和分摊到的推算消耗。

不要算「总消耗除以人数」。不要在某个情况没有记录时借用另一个人数的速度。

废弃不计入速度。盈余不计入速度。新购不计入速度。

周、月、年只用来测量速度，不表示住法会维持这么久：

- 周：最近 7 天，这是默认值
- 月：最近 30 天
- 年：最近 365 天

全应用只有一个回看设置，默认周。详情里每种情况都显示三个回看的日速度。选中的标「用于估算」，另外两个标「参考」。往前走只用选中的回看。

回看是半开区间 [现在 − D, 现在)。

日速度的分母是这个情况在该回看内的生效天数，不是 7/30/365 整个窗口，也不是人数。

判定：

- 该情况从未有过大于 0 的显式消耗或推算消耗：速度未知
- 回看内生效时长为 0：不适用（不要显示成速度 0）
- 生效时长大于 0、回看内消耗为 0、但以前有过消耗：速度 0
- 否则：日速度 = 回看内消耗量 / 生效天数

改回看之后，重算日速度，再重新往前走。

### 用完日：往前走

不要用「在手 / 当前情况的日速度」计算用完日。不要假设当前人数会一直持续。

从现在起，剩余 = 在手。不要臆造未来的购买。最多走到现在 + 366 天；那时仍大于 0，结果是「一年内不会用完」。

时刻 t 的住法：

1. 有用户写下的区间，且开始 ≤ t < 结束，结束是一个晚于现在的具体时刻：用这段。
2. 结束为「至今」的区间只覆盖到现在，不覆盖 t ≥ 现在。
3. 否则使用最近 7 天的模板。模板时刻 = 现在 − 7 天 + ((t − 现在) mod 7 天)。未来的周一用最近一个周一的住所和人数。这个 7 天模板不随回看改成 30 天或 365 天。
4. 模板时刻没有居住区间：这一小段不减任何住所的库存。

连续的同一住法作为一段：

- 住所不是该用品的住所：剩余不变。
- 住所匹配且日速度未知：停止。用完日未知，界面写明缺少哪一个「住所 + 人数」。禁止换用别的速度，禁止除以人数。
- 日速度为 0：剩余不变，继续。
- 日速度大于 0：若 剩余 / 日速度 不超过这段的天数，用完时刻 = 段起点 + 剩余 / 日速度。正好减到 0 的时刻就是用完时刻。否则剩余减去 日速度 × 段的天数，继续下一段。

只有在库存减到 0 之前遇到的未知速度才挡住结果。前面已经减到 0 时，后面的未知情况忽略。

用完日的日期是用完时刻的本地日期。

混合节奏 = 在手 / 从现在到用完时刻的天数。首页要同时显示这次行走用到的每种情况自己的日速度，以及这个混合节奏。混合节奏不能代替各情况的速度，各情况的速度也不能单独拿来除在手。

居住区间以后被补上或改过，速度和用完日都重算。

### 先到期先出

消耗、废弃、盘点推算消耗，都从剩余大于 0 的批次扣：到期日早的优先；没有到期日的最后；到期日相同则更早购入的优先。

库存不足时拒绝消耗和废弃，不能出现负库存。

### 价格

实付单价 = (购买价格 − 优惠金额) / 数量。

购买价格是优惠前总价，不是单价。价格图的纵轴是实付单价，横轴是购买时间。只有新购批次进入价格图。盘点盈余不进入。

同一住所、品牌和规格相同（去掉首尾空白）的新购并入同一个用品。另一个住所即使品牌规格相同，也是另一个用品、另一张图、另一套库存。

选中一个或多个购买点后，每个点显示：购买数量、优惠金额、购买价格、实付单价、渠道，并能打开这一笔的截图。

### 提醒（两个默认值都不要改错）

每个用品有两个独立设置：

- 快用完天数，新建时默认 **5**。首页只用这个数
- 快过期天数，新建时默认 **3**。临期页只用这个数

允许用户改成 0 到 365 的整数。0 表示只提醒已经用完，或到期日就是今天及更早。

快用完（用品，出现在首页）满足任一：

- 在手为 0
- 用完时刻已知，且用完日的日期 ≤ 今天 + 该用品的快用完天数

用完日未知且在手大于 0：不进首页。

快过期（批次，出现在临期页）同时满足：

- 剩余大于 0
- 有到期日
- 到期日 ≤ 今天 + 该用品的快过期天数

已过期会满足第三条。没有到期日的永不出现。剩余为 0 的不出现。

不要把默认值做成 14 天或 30 天。不要用一个全局阈值覆盖用品自己的设置。不要因为快过期就把用品放进首页，也不要因为快用完就把批次放进临期页。

### 居住区间

一段时间里只有一个住所、一个人数。区间含起点、不含终点。任意两段不能重叠；重叠时保存失败，指出冲突的那段，不要自动改旧数据。首尾相接可以。

提供快速设置：住所、人数（≥ 1 的整数）、开始、结束（结束可为「至今」）。

提供「从现在起改为……」：结束当前区间并开始新区间。两步是一次事务，失败则全部回滚。这个操作不移动库存。「至今」不把新人数铺满未来。

没有居住区间时仍可记账。那些消耗在速度里未归属，并提示用户补区间。

用户要把将来某几天算进预测，必须写下结束时间晚于现在的区间。没写的未来日子按最近 7 天的星期重复。

### 删除住所

必须确认。确认框写明用品数、批次数、截图数，以及历史会被永久删除、库存不会转到别的住所。取消则不删。确认后删除该住所的用品、批次、事件、区间和照片文件。不要自动激活另一个住所。

## 数据与重放

用 Room 保存住所、居住区间、用品、批次、截图索引、记账事件、事件的批次扣减、应用设置（速度回看，默认周）。

在手和速度由事件按时间重放得到，不要只改一个无法回溯的库存数字。同一时刻的顺序：新购、废弃、显式消耗、盘点，然后是保存顺序。

新购保存后，数量不可改。购买价格、优惠、渠道、到期日和截图可以改。消耗、废弃、盘点、新购可以删除。删除或修改后整段重放。若重放会导致某笔扣减超过当时库存，拒绝并告诉用户是哪笔挡住了。

用品字段至少包括：住所、品牌、规格、单位、快用完天数、快过期天数。

批次至少包括：用品、来源（新购或盘点盈余）、时刻、原始数量、剩余、价格（分，可空）、优惠（分，可空）、渠道（可空）、到期日（可空）。

事件要能重算出每一次盘点的账面、推算消耗和盈余。

## 照片

用户从相册选择一张或多张图片。选择后立刻复制到应用私有目录，例如 `filesDir/purchase_photos/<批次id>/<图片id>.jpg`。Room 只存相对路径。以后不要依赖相册原 URI。

截图只属于那一笔新购。用品详情的价格历史里，选中购买点后可以打开。多张可以切换。文件丢失时显示「截图文件丢失」，不要崩溃。删除批次或住所时删除文件。

不要上传。不要申请不必要的网络权限。

## 界面行为

- Material 3，跟随系统深浅色
- 首页快用完一行要有：名称、在手、这次行走用到的每种情况的日速度、混合节奏、用完时刻、该用品的快用完天数
- 不要在首页只写一个「当前人数的速度」，也不要用那个速度单独除在手
- 排序：在手为 0 在前，然后按用完时刻从早到晚
- 用品详情列出往前走的每一段：日期、星期、住所、人数、减去多少、剩余多少
- 详情里每种相关情况展示周、月、年三个速度，标出哪一个用于估算
- 用完日未知时写明缺少的情况，例如「家·2人 没有消耗记录」
- 临期一行要有：名称、剩余、到期日、已过期几天或还要几天、渠道、该用品的快过期天数
- 排序：已过期在前，然后按到期日
- 价格图支持多选。未选中时提示点选。选中项按时间列出上文规定的字段
- 没有购买时，图的位置是空状态「还没有购买记录」
- 没有住所、没有用品、没有快用完、没有临期、速度未知，都要有明确中文说明，不要留白屏
- 新购表单实时显示实付单价
- 点数表单显示账面，并在提交前显示推算消耗或盈余
- 消耗若落在本住所居住区间之外，先警告：库存会减少，但这笔不进入速度
- 校验失败时用中文说明原因：数量、优惠大于总价、渠道为空、库存不足、区间重叠
- 住所页说明：「至今」不铺满未来；要锁定将来某几天，把结束时间写到将来

空状态文案要能让人知道下一步去哪：建住所、设置人数、记一笔新购。不要预置示例用品。

提醒只做应用内列表。不要系统通知，不要桌面小组件，不要条码扫描，不要分享，不要登录。

## 数值验收（做成单元测试）

把「现在」固定为 2026-05-04 00:00（星期一）。用这些数据断言，不要只做近似的界面演示。

住所「家」。用品清风 / 130抽×6 / 提。快用完天数 5，快过期天数 3。速度回看为周。

居住区间：

- 家，1 人，[2026-04-27 00:00, 2026-05-02 00:00)
- 家，2 人，[2026-05-02 00:00, 2026-05-04 00:00)

没有覆盖 2026-05-04 及以后的区间。

事件：

1. 2026-04-27 00:00 新购 16。购买价格 11200 分，优惠 1600 分，渠道超市，到期 2026-06-30。实付单价 = 6 元/提
2. 2026-04-28 12:00 显式消耗 2
3. 2026-04-29 12:00 废弃 1
4. 2026-04-30 00:00 盘点实盘 10。断言账面是 13，推算消耗是 3，盈余是 0
5. 2026-05-03 12:00 显式消耗 4

然后断言：

- 在手为 6。16 − 2 − 1 − 3 − 4 = 6
- 家·1人的消耗是 5（显式 2 + 推算 3），不是 7，也不是 8。废弃的 1 没有进入速度，显式的 2 没有在推算里再算一次
- 家·1人的周日速度是 1 提/天（5 / 5 天）
- 家·2人的周日速度是 2 提/天（4 / 2 天）。不是 1 提/天，也不是 4 / 2 / 2
- 这个例子里月回看和年回看的两个日速度也是 1 和 2，因为更早没有消耗。回看改成月，不会把某一种人数延长成 30 天
- 用完时刻是 2026-05-09 12:00。行走是：05-04 到 05-08 每天按家·1人减 1，05-09 按家·2人从剩余 1 走到当天的一半
- 混合节奏是 12/11 提/天（6 / 5.5 天）。首页同时能看到 1 提/天、2 提/天和这个混合节奏
- 用完日 2026-05-09 ≤ 2026-05-04 + 5 天，该用品在快用完列表
- 把快用完天数改为 4 后，它退出快用完列表。用完时刻不变。这不改变临期结果
- 不要得出「6 / 2 提每天 = 3 天」或「6 / 1 提每天 = 6 天」。那是假设单一人数持续，本例禁止
- 到期 2026-06-30 的批次不在临期列表
- 价格图有一个点，实付单价 6 元。没有盈余批次

再断言这些行走变体：

- 另加父母家 [2026-05-06 00:00, 2026-05-07 00:00)。05-06 清风的剩余不变。用完时刻变为 2026-05-10 00:00。混合节奏变为 1 提/天（6 / 6 天）
- 删掉 05-03 的显式消耗后，家·2人速度未知。走到 2026-05-09 时用完日未知，原因点名家·2人。不能改用家·1人的速度
- 在手改为 5，且家·2人速度未知时，用完时刻是 2026-05-09 00:00，因为在用到星期六之前已经减完

另造数据断言提醒和扣减，不要和上面的行走混在同一用品里：

- 剩余大于 0、到期 2026-05-06、快过期天数 3：出现在临期列表。天数改为 1 后不出现
- 到期 2026-05-03 且仍有剩余：即使快过期天数是 1，也出现
- 没有到期日的批次不出现；剩余为 0 的不出现
- 两个批次，甲到期 2026-05-20 剩余 1，乙到期 2026-06-01 剩余 5。消耗 2 后甲剩余 0、乙剩余 4
- 同样两批，废弃 2 后库存分配相同，但所有情况的速度不变
- 在手为 0 的用品即使速度未知也在快用完列表

再断言这些失败路径：

- 消耗大于在手被拒绝
- 优惠大于购买价格被拒绝
- 居住区间重叠被拒绝，旧数据不变
- 删除住所在确认前数据还在

## 完成标准

在调试构建里能够：创建两个住所；为它们分别设置互不重叠的人数区间；在各自名下新购并看到分开的库存；给购买加上截图并从价格历史打开；记录消耗、废弃和点数；首页一行同时看到有关情况各自的速度和混合节奏；没写下的未来按最近 7 天的星期重复，而不是把当前人数一直延续；首页与临期按每个用品自己的 5 天和 3 天默认值（以及改过的值）分开出现；切换速度回看后重新测量速度并重新往前走，星期模板仍是 7 天。
