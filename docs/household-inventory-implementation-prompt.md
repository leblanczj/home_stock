# 实现提示词：家庭日用品库存 Android 应用

把下面从「你要做的事」到文末整段复制给实现用的 AI。不要再写一份设计，直接做出能安装运行的应用。

---

你要做的事：在一个空的 Android 工程里实现「家庭日用品库存」手机应用，并让它真正可运行。直接写代码、界面和测试。不要留空页面，不要用假数据充页面。

这是单用户、一部手机、本地优先。不要账号，不要登录，不要后端，不要网络同步。卸载前数据只在这台设备上。

## 技术栈（锁定）

- Kotlin
- Jetpack Compose
- Material 3
- Room
- 购买截图存在应用私有目录
- minSdk 26
- 当前稳定的 Compose、Room、Kotlin
- 界面文案用中文
- 库存重放、分摊、用完日、提醒判定写成不依赖界面的纯 Kotlin，并用 JVM 单元测试覆盖下文的数字。禁止只用二进制浮点做金额和数量加减

金额用人民币「分」。数量内部用毫单位（1 个单位 = 1000）。界面最多显示三位小数。

## 用户能看见什么

用户只录入：新购、点数、消耗、废弃，以及一段时间的住所和居住者。

首页每一行只有三个结果：在手数量、一个消耗速度、一个用完时间。再加该用品自己的快用完天数。

不要在界面上出现算法名称、权重、5/7、2/7，或每一组居住者各自的速度。设置里可以有「统计范围：周 / 月 / 年」，默认周，说明只用这段时间的记账来估计用量。不要把权重解释给用户。

底部三个入口：首页、临期、住所。

- 首页：快用完的用品、四个记账入口、进入全部库存
- 库存列表进入用品详情
- 详情：同一个速度、同一个用完时间、两个提醒天数、价格图、批次、记账
- 临期：快过期的批次
- 住所：增删住所、增改删居住者、为日期选择居住者

顶栏切换正在查看的住所，只改列表，不搬库存。

## 居住者

居住者是有名字的人，不是人数。全应用一份名单。

- 可以添加、改名、删除
- 改名只改显示，不重算速度
- 删除一个已经出现在历史居住里的人：旧日期仍显示删除前的名字，集合仍是原来那些 id，速度不重算。不要把 {A,B} 改成 {A}。已删除的人不能再选进新日期

一个情况 = 一个住所 + 一组居住者 id。集合必须完全相同。

- {A} 和 {B} 是两个情况，尽管都是 1 个人
- {A,B} 和 {A,C} 是两个情况
- 人数只是集合大小。录入界面没有「填人数」的框。选完人之后可以显示「2 人」，那个数字不能编辑
- 不要用成员的速度相加、平均或相减来得到集合的速度
- 不要把任何速度除以人数
- 某个集合没有自己的消耗记录时，速度未知，不能抄另一个集合

居住日期的字段：住所、开始日、结束日、至少一名居住者。开始日和结束日都算在内。星期一到星期日是 7 个日历日。

校验：

- 同一住所的日期重叠：拒绝，指出已有的一段
- 同一个人同一天出现在两个住所：拒绝，指出人和另一个住所
- 不同的人同一天分处两个住所：允许

一天在这个住所没有人：这个住所的库存不减。

## 记账

**点数**是盘点，不是购买，也不是手填消耗。

- 账面 = 这次盘点重放前的在手，已经包含上次结存后的新购、显式消耗和废弃
- 推算消耗 = max(0, 账面 − 实盘)，这是真实消耗
- 盈余 = max(0, 实盘 − 账面)，不是负消耗，不进速度，不进价格图
- 显式消耗已经从账面扣除，不会再进推算消耗

推算消耗覆盖的日历日：上次盘点日的下一天到本次盘点日，两端都算。从未盘点过，则从第一笔新购的日期到本次盘点日，两端都算。只含这个住所有人的日子。显式消耗的日子从这段天数里去掉。废弃不进入这段数量。

**显式消耗**整笔属于那一天的居住者集合。那一天没有居住记录时仍可扣库存，但提示不会进入用量估计。

**废弃**减库存，不进速度。

**新购**增加批次。同一住所、品牌和规格相同（去掉首尾空白）并入同一个用品。实付单价 = (购买价格 − 优惠金额) / 数量。购买价格是优惠前总价。价格图只画新购的实付单价。选中一个或多个点时显示购买数量、优惠金额、购买价格、实付单价、渠道，并打开该笔截图。

扣减先到期先出：到期早的先扣，没有到期日的最后，同一天到期则更早购买的先扣。库存不足就拒绝，不能出现负数。

盈余批次没有价格、渠道、到期日、截图。

事件按时间重放。同一天的顺序：新购、废弃、显式消耗、盘点。删除或修改后整段重放；会造成负库存就拒绝。

## 四种后台算法

不要把这些名字显示出来。每次记账或居住日期变化后重算。权重不是用户设置。

统计范围决定哪些观测进入计算：周 = 最近 7 个日历日，月 = 30，年 = 365，默认周。范围内部仍按集合拆。未来的星期模板永远只重复最近 7 天，不随月、年变长。

一条观测的 Q 是盘点推算消耗，或一段没有逐日记录、从买下到用完的数量。显式消耗不放进 Q。

1. **整段一个集合。** 该集合得到全部 Q。日速度 = Q / 天数。权重 = 这些天的天数。
2. **按天数分。** q_s = Q × d_s / Σd。各集合的日速度都等于 Q / Σd。权重 = 混合段的天数。只有一种天数比例时用它。同样的 5 天 {A} 加 2 天 {A,B} 重复多少次，都不能分开两个日速度。
3. **不同的天数组合。** 仅当互相一起出现的集合不超过两个，且回看里至少有两种不同的天数比例、并且下面的 Δ 不为 0。权重 = 这些观测的天数。同一批观测不再同时计入算法 1 和 2。第三个互相耦合的集合不要用通用求解器，退回算法 1 和 2。没有出现在同一段里的集合分开算。
4. **记了具体某一天。** 显式消耗整笔属于那天的集合。权重 = 这样的天数。这些天不再进入算法 1 到 3。

两个集合的直接解。观测 i 的天数是 d_i、e_i，数量 Q_i：

- Sdd = Σ d_i²，See = Σ e_i²，Sde = Σ d_i e_i
- Td = Σ d_i Q_i，Te = Σ e_i Q_i
- Δ = Sdd × See − Sde²
- Δ = 0：分不开，算法 3 的权重为 0
- r_d = (Td × See − Te × Sde) / Δ
- r_e = (Te × Sdd − Td × Sde) / Δ
- 小于 0 的那个改为 0，另一个改为 Σ(天数 × Q) / Σ(天数²)；分母为 0 则为 0

分完之后 q_s = Q × (d_s × r_s) / Σ(d × r)，各份之和必须等于 Q。分母为 0 时退回按天数分。

集合的日速度 = 各算法为它给出的日速度的加权平均。没有给出的算法不参加。

## 用完时间

剩余从在手开始。未来某一天：

- 该住所已写下的日期盖住它：用写下的集合
- 否则用该住所最近 7 天里同一个星期几的集合；那天没有人，就不减

减去的是该集合的合并日速度。未知就停止，速度和用完时间都显示「无法估算」。不要抄别的集合，不要除以人数，不要用成员拼一个速度。速度为 0 则当天不减。剩余到 0 的时刻是用完时间；正好用完整数天时，用完时间是次日 0 点。

首页那个速度 = 在手 / 走到用完的天数。它必须和用完时间一致。在手为 0 时用完时间写「已经用完」。最多走 366 天，仍有剩余则「一年内不会用完」。

## 提醒

每个用品两个整数，0 到 365：

- 快用完天数，默认 **5**。首页用它
- 快过期天数，默认 **3**。临期页用它

快用完：在手为 0，或用完日的日期 ≤ 今天 + 快用完天数。未知且在手大于 0 不进首页。

快过期：批次剩余大于 0、有到期日，且到期日 ≤ 今天 + 快过期天数。已过期也算。没有到期日或剩余为 0 的不出现。

不要把默认值做成 14 天或 30 天。两个列表不要互相掺。

## 照片和其他界面

选图后复制到 `filesDir/purchase_photos/<批次id>/<图片id>.jpg`。Room 只存相对路径。丢失时显示「截图文件丢失」。删除批次或住所时删文件。不要上传。

Material 3，跟随系统深浅色。空状态用中文说明下一步：添加居住者、写下住在哪、记一笔新购。不要预置商品。

点数提交前显示账面，以及将记入的推算消耗或盈余，不要显示内部分摊分数。

删除住所必须确认，写明用品、批次、截图会被删除且不会转移。取消则不删。居住者名单保留。

新购数量保存后不可改。价格、优惠、渠道、到期日、截图可以改。

不要系统通知、小组件、条码、分享、登录。

## 数值验收

用精确分数断言内部结果。首页模型只暴露在手、一个速度、一个用完时间。

居住者 A、B。住所「家」。单位「包」。快用完 5，快过期 3。

**第一周，现在 = 2026-05-11。** 居住：

- 2026-05-04 至 2026-05-10：周一到周五 {A}，周六日 {A,B}

事件：

1. 2026-05-04 新购 2。购买价格 2000 分，优惠 0，渠道超市，到期 2026-06-30。实付单价 = 10 元/包
2. 2026-05-10 盘点实盘 1。账面 = 2，推算消耗 = 1，盈余 = 0，在手 = 1

断言：

- {A} 分到 5/7 包，{A,B} 分到 2/7 包
- 两者日速度都是 1/7 包/天
- 算法 3 的权重是 0
- 再复制一周完全相同的 5+2，权重仍是 0
- 首页：在手 1，速度 1/7 包/天，用完时间 2026-05-18 00:00
- 05-18 晚于 05-11 加 5 天，不在快用完列表
- 06-30 的批次不在临期列表

**第二周，现在 = 2026-05-18。** 2026-05-11 至 2026-05-17 每天只有 {B}。2026-05-17 盘点实盘 3/10。账面 = 1，推算消耗 = 7/10，在手 = 3/10。

断言：

- {B} 的日速度是 1/10 包/天
- 这个速度不是 {A} 的 1/7，也不是 1/7 除以 1，也不是 {A,B} 的速度除以 2
- 算法 3 的权重仍是 0。{B} 这一周不能把 {A} 和 {A,B} 拆开
- 默认周回看只含这 7 天。首页速度是 1/10 包/天，用完时间是 2026-05-21 00:00
- 改成月回看后，后台仍可有 {A} = 1/7、{A,B} = 1/7，但 {B} 的日子仍减 1/10。首页速度不能变成 (5/7 + 7/10) / 12 = 33/280
- 05-21 ≤ 05-18 + 5 天，进入快用完列表。快用完天数改为 2 后退出，用完时间不变

**算法 3 的独立观测，不要和 {B} 那一周混在同一个首页结果里：**

- {A} 5 天、{A,B} 2 天、Q = 1
- {A} 7 天、Q = 7/10

断言 r({A}) = 1/10 包/天，r({A,B}) = 1/4 包/天，第一包改分为 1/2 和 1/2，算法 3 权重 14，算法 2 对这两条的权重为 0。{B} 得不到这两个速度。

再用这两个速度、在手 1 包、未来前 3 天 {A}、后 4 天 {A,B}：用完时间在 29/5 天处，首页速度 = 5/29 包/天。界面仍只有这一个速度。

**另造数据：**

- 剩余大于 0、两天后到期、快过期天数 3：在临期列表。改为 1 天后不在
- 已经过期且仍有剩余：快过期天数是 1 也在
- 没有到期日，或剩余为 0：不在
- 先到期的批次剩余 1、后到期的剩余 5，消耗 2：先到期的变为 0，后到期的变为 4
- 同样两批废弃 2：库存相同，所有集合的速度不变
- 在手为 0：即使速度未知也在快用完列表
- 显式消耗已经扣过账面后再盘点：推算消耗不含那一笔
- 同一个人同一天写入两个住所：拒绝
- 同一住所日期重叠：拒绝
- 删除已使用的 B：旧的 {A,B} 仍可读，速度不重算
- 消耗大于在手、优惠大于购买价格：拒绝
- 删除住所在确认前数据还在
